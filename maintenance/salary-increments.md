# Kenaikan gaji pokok berkala

Program dimulai Oktober 2026 sesuai keputusan pengguna. Pegawai dengan gaji pokok lebih dari Rp0 dan kurang dari Rp3.000.000 memperoleh kenaikan Rp250.000 setelah mengumpulkan enam bulan yang memenuhi disiplin. Bulan memenuhi syarat jika telat masuk pagi paling banyak tiga kali dan alpa paling banyak dua hari; izin tidak digabungkan ke batas ini. Bulan melanggar dilewati tanpa mereset akumulasi. Setiap enam bulan hanya digunakan sekali. Kenaikan terakhir dibatasi sampai Rp3.000.000; setelah batas tercapai program otomatis selesai permanen. Manajemen tetap dapat menyesuaikan nominal secara manual.

Evaluasi berjalan setiap hari pukul 06.15 WITA lewat pg_cron dan pg_net. Bulan sebelumnya baru dinilai pada tanggal 6, setelah masa tenggang komponen bulanan berakhir. Kenaikan berlaku pada bulan evaluasi, bukan mengubah slip yang sudah lewat. Jadwal yang terlewat mengejar bulan yang belum dinilai secara berurutan dan tidak menggandakan kenaikan. Akun baru dimulai pada bulan penuh berikutnya, atau bulan berjalan jika dibuat tanggal 1. Pegawai tanpa gaji pokok tidak memperoleh akumulasi bulan tanpa gaji.

Perhitungan menggunakan waktu WITA dan jam masuk masing-masing cabang. Hari Ahad serta libur tambahan payroll dikecualikan. Izin/sakit yang disetujui dan kepulangan sakit tercatat diperhitungkan; pulang dini hari sebelum 06.00 mengikuti hari kerja sebelumnya. Keterlambatan setelah istirahat tidak masuk hitungan telat pagi. Profil bernama sama dalam satu cabang dilewati untuk ditinjau Manajemen agar absensi tidak tercampur.

`sla_gaji_program`, `sla_gaji_disiplin_bulan`, dan `sla_gaji_riwayat` menyimpan enrolmen, keputusan bulanan, dan riwayat nominal. Slip Gaji memakai nominal historis sesuai bulan yang dipilih dan menampilkan progres program saat ini. Pengaturan gaji manual tersedia di Profil melalui bagian **Gaji Pokok — Manajemen** bagi Admin Kendari, Manager, dan Direktur, mengikuti hak cabang. Penyimpanan menggunakan nominal lama sebagai pengaman terhadap perubahan bersamaan. Pembaruan profil biasa tidak menulis ulang gaji pokok.

Setiap kenaikan otomatis maupun manual membuat antrean WhatsApp pegawai dalam transaksi yang sama. Antrean menggunakan nomor pada profil terkini, lease untuk mencegah pengiriman bersamaan, dan mencoba ulang kegagalan pada jadwal harian berikutnya. Fonnte menandai pengiriman diterima hanya jika respons provider sukses; kegagalan WhatsApp tidak membatalkan gaji yang sudah tersimpan. Antrean ini tidak menjanjikan jaminan exactly-once jika provider berhasil menerima pesan namun koneksi putus sebelum status tersimpan.

Pemasangan: jalankan `salary-increments.sql`, lalu `salary-increments-schedule.sql` pada proyek Supabase. Publikasikan Edge Function `sla-payroll-attendance` dan frontend. Panggil `sla_installer_automatisasi_gaji(p_server_key)` dari koneksi server yang terautentikasi dengan key server yang sudah ada untuk menyimpan key yang sama terenkripsi di Vault dan memasang job `sla-kenaikan-gaji`. Gateway tidak meneruskan header apikey asli ke PostgreSQL, sehingga pemasangan menerima key sebagai parameter server, tanpa mengetiknya di browser. Key tidak ditulis ke source atau perintah cron. Jadwal `sla-finalize-attendance` tidak diubah. API cron menolak key publik dan token pengguna, dan tidak menerima tanggal evaluasi dari pemanggil.

Validasi otomatis: `node --test maintenance/salary-increments-database.test.cjs tests/salary-increments-edge.test.cjs`. Validasi browser lokal memakai data tiruan dan memblokir semua permintaan produksi; pengujian tidak menaikkan gaji atau mengirim WhatsApp sungguhan. Tidak ada riwayat sebelum Oktober 2026 yang dievaluasi saat pemasangan.
